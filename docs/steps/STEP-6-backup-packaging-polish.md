## Tasks

### 6.1 Backup container (`docker/backup/`)
- An alpine-based image (multi-arch) with: `postgresql18-client` (it **must** match the server major version), `restic`, `rclone`, `supercronic`, `curl`, `jq`, `tzdata`. TZ=Asia/Colombo.
- `backup.sh` (idempotent, `set -euo pipefail`, logs to stdout):
  1. Insert a `BackupRun` (RUNNING) via `psql`.
  2. `pg_dump -Fc` → `/work/db/supun.dump`.
  3. Mirror the SeaweedFS bucket to `/work/files` with `rclone sync` (an S3 remote configured from env, `provider=SeaweedFS` or `Other`, path-style).
  4. `restic backup /work` to the **local repo** (`/backup-local`, docker volume `backup_local`) — always.
  5. If a Google Drive remote is configured (`/config/rclone/rclone.conf` contains `[gdrive]`): `restic -r rclone:gdrive:SupunConstructionBackup backup /work`.
  6. `restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 12 --prune` on each repo (prune weekly only, e.g. on Sundays, to save time).
  7. Update the `BackupRun` → SUCCESS/FAILED with the size, destination and a short message (on any failure: trap → FAILED + error tail).
  - The repos are initialised automatically when missing (`restic init`). `RESTIC_PASSWORD` comes from `.env`, generated by `start.command`. **Warn clearly in the README: write this password down — without it backups cannot be restored.**
- `worker.sh` (the container command): run supercronic with the crontab (`0 23 * * *` backup) **and** a loop every 60 s that checks `BackupRequest` for unpicked rows → marks picked → runs `backup.sh` (lock with `flock` so runs never overlap). Also run a catch-up backup on container start if the last SUCCESS is older than 24 h (the MacBook may have been asleep at 23:00).
- `restore.sh` (+ `scripts/restore.sh` host wrapper): list snapshots (local or gdrive), choose the latest or a given ID, stop api/web, restore into `/restore`, `pg_restore --clean --if-exists` into the DB, `rclone sync` the files back into the bucket, start api/web. It needs a typed confirmation.
- Add the `backup` service to `docker-compose.yml` (depends on postgres + seaweedfs healthy; volumes: `backup_local`, `./config/rclone` read-write; no ports).

### 6.2 Google Drive connection
- Research the simplest reliable way for a non-technical user on macOS to authorise rclone for Google Drive (e.g. `scripts/setup-gdrive.sh` that installs or uses the rclone binary on the Mac for `rclone authorize "drive"`, or runs `rclone config` in the backup container with headless auth). Pick one, implement it, test the script logic as far as possible without real Google credentials, and document every click in the README with the exact steps. Use the `drive.file` scope if workable, otherwise `drive`. Mention the optional own-client-ID for better rate limits.
- The script writes `config/rclone/rclone.conf` (git-ignored) and runs a test (`rclone lsd gdrive:`).
- API `modules/backup`: `GET /backup/status` (last runs, last success, gdrive configured yes/no — the API learns this from the latest `BackupRun.destination` or a status row written by the container), `POST /backup/run` (inserts a `BackupRequest`), `GET /backup/runs`.
- Web Settings → **Backup** section: last successful backup (time, size, destinations), history table, "Backup now" (polls until done), Google Drive status with "How to connect" instructions. Top-bar backup dot: green (< 36 h), orange (36–72 h or local-only), red (failed/none). The dashboard attention list includes backup problems.

### 6.3 Mac packaging & scripts

- Image sizes reasonable; `docker compose build` from clean succeeds on both `linux/amd64` and `linux/arm64` (check with `docker buildx build --platform linux/arm64` for api, web and backup, at least to the build stage).
